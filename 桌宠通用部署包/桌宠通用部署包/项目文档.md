# 八向精灵片桌宠

运行：**双击 `启动桌宠.bat`** 即可；也可以手动 `\.venv\Scripts\python.exe main.py`。

## 两种启动模式

桌宠和工作台是分开启动的：

| 双击哪个 | 启动内容 |
| --- | --- |
| `启动桌宠.bat` | **只启动桌宠**：角色精灵 + 气泡 + 聊天输入框，不打开工作台面板 |
| `启动工作台.bat` | 桌宠 + **工作台面板**（动作/素材、API、提示词、知识库、日志都在这里配） |

需要看报错时用调试版（保留控制台窗口，报错不会一闪而过）：

| 双击哪个 | 启动内容 |
| --- | --- |
| `调试桌宠.bat` | 桌宠 + 控制台 |
| `调试工作台.bat` | 工作台 + 控制台 |

命令行也可以：`启动桌宠.bat debug` / `启动工作台.bat check`（`debug` 保留控制台，`check` 只做环境自检）。

> **两种模式不能同时开。** 工作台本身就带着桌宠，所以同时开会出现两只桌宠、并且两个进程会抢同一个 `memory.db`。程序用 `.lilyz.lock` 文件锁拦住第二个实例，并提示你先关掉正在运行的桌宠。

## 启动器的自动处理

`启动桌宠.bat`（工作台入口也会调用它）会自动查找可用的 Python（支持 `py`、PATH 里的 python、Anaconda、官方安装目录）、按需创建 `.venv`、按需安装 `requirements.txt`，然后启动。

> 注意：Microsoft Store 里的 `python` 是个占位程序，不能用来建虚拟环境；启动器会自动跳过它并去找真正的 Python（例如 Anaconda）。

发布安全：不要分发 `config.json`、`memory*.db` 或 `knowledge.json`。复制 `config.example.json` 为 `config.json` 后保持 `api_key` 为空，用户自行填写；也可使用环境变量 `LILYZ_API_KEY` 和 `LILYZ_BASE_URL`，环境变量优先且不会写回文件。

### 打成「通用部署包」发给别人 / 换台电脑

直接跑 `打包发布.py`（`.venv\Scripts\python.exe 打包发布.py`），会在根目录生成 **`桌宠通用部署包.zip`**——

- **只含引擎**：18 个 `.py`、4 个启动脚本、`requirements.txt`、两份文档（`README.md` 是**从零部署的详细步骤**，`项目文档.md` 是本文件的脱敏副本）；
- **不含**任何 Key / 中转站域名 / 个人路径 / 录音文件名 / `memory*.db` / `app.log` / `.venv` / `models`；
- 换成一份**现画的占位角色**（纯几何图形，八个方向 + 无方向待机）和一份示例人设，所以不涉及任何第三方素材；
- 打包脚本自己会做三重复检，任何一步不过就报错退出：① 扫包内有没有 Key/域名/个人路径等私人痕迹；
  ② 把包解压到临时目录跑 `语气自测.py`；③ 在解压目录里**离屏启动一次**，确认能起来、素材被正确识别、日志无异常。

> 想带上自己的角色（你自己的素材 + 人设）一起发：把 `assets/characters/<角色目录>` 和 `prompts/persona.json`
> 拷进解压后的包里即可。注意游戏提取的立绘是有版权的，分享前想清楚。

将透明 PNG 放入 `assets/motions/idle/N` 等八个方向目录，文件名按 `00.png`、`01.png` 排序播放。控制面板可设置动作、方向、帧间隔、正倒序及鼠标跟随。按住桌宠左键可拖动。

## 语音输入

聊天窗口里输入框左边有个「语音」按钮：**点一下开始录音，再点一下结束并识别**。识别结果会**先填进输入框**而不是直接发出去——语音识别难免出错，留给你改一眼再按回车更稳妥。

录音用 PySide6 自带的 QtMultimedia，**不需要装任何新依赖**；录成 16kHz 单声道 16bit 的 WAV（各家识别服务都吃的通用格式）。超过 30 秒会自动停，避免忘了按停。

### 三种识别方式（⚙ → 语音输入设置）

| 方式 | 说明 |
| --- | --- |
| **本地离线识别 vosk**（默认） | 随项目附带的中文模型（约 42MB，在 `models/`），**免 Key、不联网**。比系统自带引擎新得多，短句识别明显更准 |
| Windows 自带离线识别 | 用系统内置的 `System.Speech` 引擎，免安装，但用的是上世纪的技术，准确率较低 |
| 云端识别 | 任何 OpenAI 兼容的 `/v1/audio/transcriptions` 接口。实测可达：**硅基流动 SiliconFlow**（`FunAudioLLM/SenseVoiceSmall`，有免费额度）、**Groq**（`whisper-large-v3`）、智谱。最准，需要 Key |

设置界面里有「**检测语音输入**」按钮，会分别报告录音设备和识别引擎是否真的可用——它不只是查列表，而是**真的试着启动一次引擎**，避免报「可用」却发现用不了。

### 录音预处理

识别前会先把音频收拾一遍，这一步对准确率影响很明显：

- **去掉首尾静音**：一长段静音会让引擎的端点检测跑偏
- **音量归一化**：麦克风增益偏低时字音会糊在一起（实测遇到过只有满量程 9% 的）

`app.log` 里会记下「峰值 X -> Y，放大 N 倍」。**如果放大倍数很大，说明麦克风输入音量偏小**，去系统声音设置里调高输入增益，识别率会进一步改善。

### 相关配置

| 配置项 | 说明 |
| --- | --- |
| `asr_provider` | `vosk`（本地）/ `windows`（系统）/ `openai`（云端）/ `off` |
| `asr_language` | 识别语言，默认 `zh-CN` |
| `asr_vosk_model` | 自定义 vosk 模型目录，留空用 `models/vosk-model-small-cn-0.22` |
| `asr_url` / `asr_api_key` / `asr_model` | 云端方式的地址、Key、模型名 |
| `asr_timeout` | 云端识别超时（秒） |

## 语音输出（角色说话）

角色回复可以**读出来**。聊天窗口里按钮行有一个「**静音**」开关：**勾上 = 角色不朗读，取消勾选 = 角色把回复读出来**。之所以叫「静音」而不是「朗读」，是因为默认是关的——空着的勾选框就代表「会读」，一眼就知道现在会不会出声，不用反着想。状态会写进 `config.json`（`tts_enabled`），下次启动保持不变。勾上静音会**立刻掐掉正在播的那句**。合成失败不影响对话本身——语音是单独的任务，出错只记日志。

用的是阿里云百炼（DashScope）的语音合成，走 HTTP，不需要 WebSocket、不需要额外 Python 依赖；播放用 PySide6 自带的 QtMultimedia。云端有两条路可选——**Qwen-TTS**（音色多、复刻用 base64 本地文件）和 **Qwen-Audio-TTS**（语气最强、复刻要公网音频），详见下面各自的小节。

> ⚠ **要用一条新的百炼 API Key**。你现在用的中转站 Key、DeepSeek Key 都不行——语音合成是百炼独有的接口，拿别的 Key 打过去只会 404/401。开通入口：百炼控制台 → API-KEY。

### 设置（⚙ → 语音合成设置）

| 项 | 说明 |
| --- | --- |
| **启用** | 等同于聊天窗口里的「静音」开关（勾上启用 = 不静音） |
| **合成方式** | 三选一：**云端 · 阿里云百炼 Qwen-TTS**（音色多、快，按量计费）／ **云端 · Qwen-Audio-TTS**（**语气最强**，可复刻音色，但音色与 Qwen-TTS 不通用）／ **本地 · GPT-SoVITS**（自己的服务，免费离线，CPU 慢）。切换后下面的参数页跟着换 |
| **音量** | 0–100（两种方式共用，作用于播放器） |

云端那一页（自建音色也在这里）：

| 项 | 说明 |
| --- | --- |
| **百炼 API Key** | 北京地域的 Key。**新加坡与北京的 Key 不通用** |
| **合成模型** | 普通朗读用 `qwen3-tts-flash`；要**语气**必须用 `qwen3-tts-instruct-flash`；用自建音色时必须换成它的驱动模型（`qwen3-tts-vd-2026-01-26` / `qwen3-tts-vc-2026-01-22`），但驱动模型**不认语气** |
| **音色** | Cherry（芊悦）、Serena（苏瑶）、Ethan（晨煦）、Chelsie（千雪）、Momo（茉兔）、Nofish（不吃鱼）、Dylan（北京话）、Sunny（四川话），也可直接手填音色名 |
| **语气** | 见下面「语气」一节：填了才会合成时套用、也才会允许模型按句写 `[语气:…]` |

本地那一页见下面「本地语音合成（GPT-SoVITS）」。

### 试听（改完音色马上听）

音色表单正下方就是「**试听 · 输入文本，用上面选的音色读出来**」，**三种合成方式都能用**：

- 在框里**随便打一段字**，点「**用当前音色试听**」，就用上面选中的**音色 + 合成模型**（本地则是参考音频）合成并播放，状态栏会写明用的是哪个引擎/音色、多少字节
- 试听文本会随「保存」一起存进 `tts_audition_text`，下次打开还在
- **复刻/设计完音色后会自动用它读一段**（复刻接口本身不返回试听音频，所以是直接合成一句给你听）；想再听别的内容，改试听框再点一次即可
- 「**检测**」按钮只查环境（Key、模型、播放器、音色/参考音频是否齐），本地方式会**额外探测一次端口**；只有「用当前音色试听」才真的去合成

> 声音设计那一组里的「预览文本」只在**创建音色**时用（生成平台自带的预览音频），日常试听请用这个试听框。

### 语气（让角色决定「怎么说」，不只是「说什么」）

Qwen-TTS / Qwen-Audio-TTS 都支持用**人话**描述怎么读这句话。桌宠里有**三层**可以写，从「只管一个角色」到「只管一句话」：

| 层 | 写在哪 | 管什么 | 建议 |
| --- | --- | --- | --- |
| ① 角色层（**最推荐**） | `prompts/persona.json` 里的 `tts` 块 | 只影响这个角色；换角色就跟着换 | 角色的固定说话风格写这里，例如「语速偏慢、字句轻柔、尾音轻落」 |
| ② 全局层 | ⚙ → 语音合成设置 → 各页里的 **语气** | 所有角色共用的默认语气 | 填一条通用底线，或干脆留空 |
| ③ 单句层（自动） | 模型自己在每句前面写 `【语气:说明】` | 只影响那一句 | 由下面那段「语气标注提示词」引导出来，**不用你写** |

**角色层**（换角色自动换语气）：

```json
"tts": {
  "instructions": "语速偏慢、字句轻柔、尾音轻落，温柔克制，别太活泼",
  "optimize_instructions": true,
  "model": "",
  "voice": ""
}
```

`model` / `voice` 留空就沿用设置里的；填了就只对这个角色生效（比如给某个角色单独配一个音色）。
「语气」那一栏是**全局**的，persona 里写了就以 persona 为准。

**单句层**怎么来的：靠的是一段**每次都发**的「语气标注提示词」（下面单独一节）。模型按上下文给每一句
标一个语气，**标记本身既不显示在气泡里、也不会被念出来**；没标就整段用默认语气。

```
【语气:小声】我、我才没有偷看……【语气:慌乱】啊，别看我！
```

### 语气标注提示词（那一块恒输入的提示词）

这是「让模型按上下文自己决定每句怎么读」的地方：**独立一段、每轮对话都注入**，
和页面里那个「语气」框（那句「该怎么读」的默认值）是两回事——
前者教模型**怎么标注**，后者给合成接口一个**默认语气**。

在哪改：

| 层 | 位置 | 说明 |
| --- | --- | --- |
| 全局 | ⚙ → 语音合成设置 → 顶部 **语气标注提示词** 那个框 | 可编辑，带「恢复内置默认」；右边的勾选框控制要不要发 |
| 角色 | `prompts/persona.json` 的 `tts.tone_prompt` / `tts.tone_prompt_enabled` | 按角色覆盖，**优先于全局** |
| 配置 | `config.json` 的 `tone_prompt` / `tone_prompt_enabled` | 留空就用内置默认那段 |

内置默认那段说的是：**每一句话**都单独判断语气，写成 `【语气:说明】`，说明要短、要贴合上下文，
不同句子可以用完全不同的语气，没特别之处就写「平常」；标记用户看不到、也不会被读出来。

**它真的会按上下文变** —— 用你现在的聊天模型（`你的聊天模型`）跑了两遍，同一句台词只换情境：

| 场景 | 模型给这句话标的语气 | 合成时长 |
| --- | --- | --- |
| 玩家说「这次是我赢了，轮回终于被我打破了。你输了。」 | `小声不甘` | 3.36 秒 |
| 玩家说「我又失败了……什么都救不了，我累了。」 | `低落` | 4.56 秒 |

同一段回复里也会逐句不同，例如「心疼而轻柔」的安慰 + 「低落」的感慨 + 「小声挽留」的收尾。
（当时留下的对照音频文件已经清掉了——想自己听，在设置页的试听框里直接写一句 `[语气:非常缓慢，拖长每个字] 你好呀` 就行。）

> ⚠ 标出来的语气**只有认语气的合成方式才生效**：Qwen-Audio-TTS、`qwen3-tts-instruct-flash` 认；
> 本地 GPT-SoVITS 不认——那种情况下标记仍然会从正文里去掉（不会念出来），但读法不变。
> 用不上的话，把那个勾选框关掉就行（省 token）。

真机跑通的样子（`qwen3-tts-instruct-flash` + Cherry，走的就是角色朗读的同一条代码路径）：
第一句带「非常缓慢、拖长」合成出 **5.44 秒**，第二句带「非常快、急促」**1.84 秒**，两次请求。

> ⚠ **只有 `qwen3-tts-instruct-flash` 真的认语气，而且它不吃复刻音色。** 这是实测出来的
> （同一句话各发两次，看时长区间是否重叠，而不是看单次差值）：

| 合成模型 | 不加语气 | 加「缓慢、拖长」 | 结论 |
| --- | --- | --- | --- |
| `qwen3-tts-instruct-flash` | 3.60~3.76 秒 | 5.92~6.48 秒 | **认**（「快、急促」2.64~2.80 秒，两个方向都认） |
| `qwen3-tts-flash` | 3.28~3.92 秒 | 3.28~3.36 秒 | 区间重叠，**不认** |
| `qwen3-tts-vc-2026-01-22`（复刻音色） | 3.76~4.16 秒 | 3.68~4.80 秒 | **不认**：接口收下这个字段但不用它 |

所以：

- 想用语气 → 把「合成模型」改成 **`qwen3-tts-instruct-flash`** + 一个**系统音色**（Cherry / Chelsie…）。试听框里直接写 `[语气:非常缓慢，拖长每个字]` 就能立刻听出区别；
- 想用**复刻音色**（自己的录音）→ 语气不生效，日志里会留一条 `模型 xxx 不认语气指令，已忽略`，试听状态栏也会直说「语气：不生效」；
- 两者都想兼得、或者嫌语气不够强 → 换 **Qwen-Audio-TTS**（下一节）。

相关配置：`tts_instructions`（语气）、`tts_optimize_instructions`（让服务端先把你写的语气改写成更好执行的版本，稍慢一点）。

改完代码想确认标记解析和「哪句用哪条语气」没坏：跑 `.venv\Scripts\python.exe 语气自测.py`（离线、不联网、不花钱，60 多项检查）。

### Qwen-Audio-TTS（语气最强的那条路）

「合成方式」切到 **云端 · Qwen-Audio-TTS**。它和上面那条**不是同一个接口**：地址是
`/api/v1/services/audio/tts/SpeechSynthesizer`，参数名是 **`input.instruction`（单数）**（Qwen-TTS 那边叫 `instructions`）。

**它的语气是实测最强的一条路**（同一句话各发两次，看区间不重叠）：

| 音色 | 不加语气 | 加「缓慢、拖长」 | 倍数 |
| --- | --- | --- | --- |
| `longanfengyue`（系统音色） | 2.40 / 2.40 秒 | 4.48 / 4.48 秒 | 1.87× |
| `longanlingxi`（系统音色） | 2.64 / 2.64 秒 | 4.96 / 4.96 秒 | 1.88× |
| `qwen-audio-3.0-tts-flash-myvoice-xxxxxx…`（**复刻音色**） | 2.56 秒 | **7.84 秒** | 3.06× |

另一组（`longanhuan_v3.6`，较长句子）：不加 3.2/3.2 秒，「缓慢、拖长」**8.88/9.2 秒**，「快、急促」**2.24/2.24 秒**
——比 `qwen3-tts-instruct-flash` 明显得多。

**逐句语气也跑通了**（走角色朗读的同一条代码路径，就是 `speak()`）：三段台词三种语气，
`[语气:小声]` → 2.48 秒、`[语气:慌乱]` → 2.72 秒、`[语气:轻而慢]` → 4.32 秒，合计 9.5 秒。

| 项 | 说明 |
| --- | --- |
| **业务空间 ID** | **可以留空**。官方推荐用 `{WorkspaceId}.cn-beijing.maas.aliyuncs.com` 专属域名，但也写明「现有域名仍可正常使用」——本机实测**留空走通用域名调用完全正常**，所以不填也行；想按官方推荐来就填上 |
| **合成模型** | `qwen-audio-3.0-tts-flash`（便宜快）／ `qwen-audio-3.0-tts-plus`（更好更贵）。两者的**音色表不同** |
| **音色** | 龙安风月／元妃／凌汐／心心／欢、龙泡泡、龙杰力豆、龙火火、龙川蜀、loongeva、loongjohn、loongmary。另有 500 多个基础音色，名字形如 `qwen-audio-3.0-tts-flash-xxx`（官方文档里有 Excel 清单和试听包），可以**直接在音色框里手填** |
| **语速 / 音调 / 合成音量** | 0.5~2.0 / 0.5~2.0 / 0~100。注意官方说明：**降调会让整段变长、升调会变短**，要变调又不想变时长就配合语速调 |
| **采样率 / 格式** | 16000~48000 Hz，wav 或 mp3 |

> `qwen-tts-vc-myvoice-xxxxxx…` 填进来，会得到一个很含糊的 `Engine error [411]: TTS speak operation failed`

### 本地语音合成（GPT-SoVITS · 免费离线）

把「**合成方式**」切到 **本地 · GPT-SoVITS**，桌宠就不走云端了：音色由你整合包里的**参考音频**决定，免费、离线、完全自己说了算。代价是 **CPU 推理慢**（本机是 AMD 核显、无 CUDA）。

**前提：本地服务得先跑起来。** 在整合包根目录双击 `go-api.bat`，或者在设置页点「**启动本地服务**」——后者会用整合包自带的
`runtime\python.exe -I api_v2.py -a 127.0.0.1 -p 9880 -c GPT_SoVITS/configs/tts_infer.yaml`
起一个**独立进程**，并**弹出一个控制台窗口显示加载进度**（桌宠退出它也不受影响）。加载是**分钟级**的（本机实测：2 分钟以上还没就绪很常见），所以按钮会一直显示「已等 N 秒」，最多等 5 分钟。

> 那个控制台窗口是**唯一能看到加载过程**的地方（桌宠日志里只有它自己发起请求的记录）。窗口里报错、或者 5 分钟还没就绪，就把窗口内容发出来。
> 关服务：点「停止服务」（等于调 `/control?command=exit`），或直接关那个控制台窗口。

**也可以用脚本启动/体检**（`本地语音服务.py`，包里也带一份；同样功能的两个 bat 可以双击）：

```
.venv\Scripts\python.exe 本地语音服务.py check    # 体检：配置/整合包/端口/参考音频，不联网不花钱
.venv\Scripts\python.exe 本地语音服务.py start    # 启动服务（新控制台窗口显示加载进度）
.venv\Scripts\python.exe 本地语音服务.py test     # 服务起来后真合成一句，存成 本地语音测试.wav
.venv\Scripts\python.exe 本地语音服务.py ref      # 单独检查并整理参考音频（3~10 秒规则）
.venv\Scripts\python.exe 本地语音服务.py stop     # 停止服务
```

- 双击 **`启动本地语音服务.bat`** = `start`；双击 **`检查本地语音服务.bat`** = `check`（出结果后会停住，方便看）。
- `start` 会自动找整合包：命令行 `--home` → `config.json` 的 `gptsovits_home` → 常见位置（`D:\GPT-SoVITS`、桌面、下载目录等）；
  找到就**写回 config.json**，省得下次再找。加 `--dry-run` 可以只看它要执行什么命令。
- `test` 是**端到端验证**：本机实测「你好，我是回末李花子。」（11 字）→ **4.9 秒出 2.6 秒音频**（32 kHz WAV，约 164 KB）。
  这一步过了就说明整条本地链路通了，不用再去点界面。
- `check` 会把两套标准分开讲：云端复刻那套建议 10~20 秒，**本地 GPT-SoVITS 的规则是 3~10 秒**——
  脚本只报后者，不会拿云端的建议来吓你（之前那两行一起打印，看着自相矛盾）。

| 项 | 说明 |
| --- | --- |
| **整合包目录** | 用来找 `runtime\python.exe` 和 `api_v2.py`；只读，不往那边写任何文件 |
| **服务地址** | 默认 `http://127.0.0.1:9880` |
| **参考音频** | **必须放在服务端能读到的位置**（同一台机器给绝对路径即可）。**长度必须是 3~10 秒**，超了接口直接 400 |
| **参考文本** | 可留空（走 ref_free）；填了音色更准，但**必须和音频一字不差** |
| **参考语言 / 合成语言** | 参考音频是日文原声就选 `ja`，要念中文台词就 `zh`（本机默认 `ja → zh`） |
| **语速 / 切句方式 / 随机种子 / 超时** | 语速 0.5~2.0；切句一般 `cut5`；种子 `-1` 每次随机；CPU 慢就把超时放大 |

按钮：**只探测端口**（通不通）、**检测**（连配置一起看）、**启动本地服务**、**停止服务**（调 `/control?command=exit` 让它自己退）、**应用权重**。

**参考音频不是上传的**：`api_v2.py` 里那个上传音频的接口被作者注释掉了（源码 526~542 行），所以只能传「服务端本机路径」。以后若把服务放到别的机器上，得用共享目录——这一条会直接决定你的架构。

**参考音频必须是 3~10 秒**：`TTS.py:817` 里写死了 `librosa` 读成 16k 后样本数要落在 `[48000, 160000]`，也就是 3~10 秒，否则一律 400（报错原文「参考音频在3~10秒范围外，请更换！」）。
**WebUI 的推理页也有同一条限制**（`inference_webui.py:855`）——所以「WebUI 里能用、API 里不能用」通常是因为你在 WebUI 用的是**训练**流程（训练会把长音频自动切成小段），而不是推理。

所以你**不用自己剪**：选好参考音频后桌宠会就地体检，超长就自动削掉首尾静音、再截一段（最多 10 秒）写成临时 WAV 交给本地服务，**原文件一个字节都不动**；切出来的片段缓存在 `%TEMP%\lilyz_ref_*.wav`。太短（去静音后仍不足 3 秒）或几乎没声音的会当场说清楚，不会浪费一次请求。选完文件/改完路径，状态栏里会写明它到底做了什么。

**桌宠怎么对付慢**：本地一整段要十几秒（你那边的实测：非流式首字节 **24.96 s**，`streaming_mode=2/3` 能压到 4.99 / 2.67 s，但总耗时一样）。所以我按**「值得单独合成一次的片段」**来切，边合成边播：第一段合成完立刻出声，后面的排进播放队列接着播；中途点「静音」会马上清空队列、并让还没合成完的停下。

分句规则（`voice.split_sentences`）是为「**少发请求、少接缝**」定的：

| 规则 | 为什么 |
| --- | --- |
| **只在真正的句末切**：`。！？!?`（以及换行） | `…`、`；`、`、`、`,` 都只是停顿。像「私はリカコ……あ、また言い間違えました。」这种带省略号的**一整句**，切开会读成两段、中间断一下，还多一次请求 |
| **短片段并进旁边**（`min_chars=12`） | 「あ、」「はい。」单独跑一次推理不划算 |
| **单块上限 `max_chars=45`** | 没标点的一大段硬切，免得第一句迟迟不出声 |

**本机实测 A/B**（AMD 核显、纯 CPU，参考音频 4.4 秒，句子「私はリカコ……あ、また言い間違えました。」20 字）：

| 做法 | 首音延迟 | 总耗时 | 音频 |
| --- | --- | --- | --- |
| 整句一次合成 | 5.3 s（热）/ 8.3 s（冷） | 5.3 / 8.3 s | 140–176 KB |
| 切成「私はリカコ……」+「あ、また言い間違えました。」 | **2.8 s** | 2.8 + 3.0 = **5.7 s** | 140.8 KB |

结论（说实话）：**切开并不会省总时间**，只是把首音提前；代价是同一句话被读成两段、语调在中间断掉。所以按句末切、短句合并才是对的。单次请求耗时在这台机器上波动很大（同一条文本 4.2 s 与 6.4 s 都出现过，±2 秒），上面的对比是同一条输入连测，才可比。

> 想让长回复的**首音更快**，还有一条路：`streaming_mode=2/3`（官方实测首包 4.99 / 2.67 s）。但那要边收边播（把持续增长的 wav 喂给播放器），本项目暂时没用——现在这套「短段先出声」已经能解决大部分等待感。

**本机实测**（AMD 核显、纯 CPU，参考音频 4.4 秒，句子「你好，我是回末李花子。」11 字）：**约 7 秒出一段 2.1 秒的音频**（32 kHz 单声道 WAV，约 130 KB）。比实时慢 3 倍多——所以按句来、第一句先出声，体验才不至于干等。

**自己训的模型**：整合包默认加载 **v2**。要用 v2Pro，就在设置页填权重相对路径（如 `GPT_weights_v2Pro/xxx.ckpt`、`SoVITS_weights_v2Pro/xxx.pth`）再点「应用权重」，等价于调 `/set_gpt_weights`、`/set_sovits_weights`。

| 现象 | 原因 |

#### 启动卡住时怎么查（我实测踩到的）

我在这台机器上启动它时遇到过两种失败：一次是**内存涨到 3.2 GB 后 CPU 完全不动**（卡住，端口一直不开），一次是**进程直接退出、stdout/stderr 一个字节都没有**。可用内存当时有 6 GB，所以不是单纯内存不够。这种情况**必须看整合包自己的控制台输出**——所以请**双击 `go-api.bat`**（它带 `pause`，报错不会一闪而过），把控制台里的报错发出来。常见原因：

- 显存/设备配置：`tts_infer.yaml` 的 `custom` 段写着 `device: cuda / is_half: true`，正常会自动回退 CPU 并打印两行 Warning；如果没回退就会卡在加载
- 权重/模型文件缺失或路径含非 ASCII
- 杀软拦截（整合包里的 dll 被拦会导致静默失败）
- 端口被占用（换 `-p 9881` 并同步改「服务地址」）

### 自建音色（声音设计）

不想用预置音色，可以**用一句话描述**生成专属音色，不用录音：

1. 在「自建音色 · 声音设计」里填**声音描述**（例：`年轻女性，语速偏快，语调上扬，清亮活泼，适合动画角色`）和**预览文本**（必填，创建音色时用它生成平台自带的预览音频）
2. 点「**创建音色并试听**」——通常十几秒，成功后自动把音色加进音色列表、并把「合成模型」切到驱动模型（`qwen3-tts-vd-2026-01-26`，**合成时必须用同一个模型名，否则会失败**）
3. 保存。以后想找回以前建的音色，点「**列出我的自建音色**」，选一个即可（会自动对齐模型）

几点实话：

- **每个自建音色 0.2 元**（北京地域：开通百炼后 90 天内送 10 次免费额度，创建失败不计费、删除不返还）。同一句描述每次生成的声音会略有不同，可以多建几个挑一个
- 描述文字**中英文都行**，写具体的音质特征（低沉、清亮、语速快）比写「好听」有效得多；请不要写模仿某位真人/明星，模型不支持。官方给了几个维度可组合：性别、年龄、音调、语速、情感、特点、用途
- 用的是 **Qwen 声音设计**（`qwen-voice-design` + `qwen3-tts-vd-2026-01-26`），因为它建出来的音色可以直接走 HTTP 合成。CosyVoice 那条路（`cosyvoice-v3.5-plus`）也能建音色，但合成要连业务空间专属域名的 WebSocket，本项目用不上，所以没采用
- **别把驱动模型改成 `qwen3-tts-vd-realtime-*`**（官方示例里用的就是它）：实时模型只能走 WebSocket，本项目的 HTTP 合成读不出来，界面会直接把你拦下并提示

### 自建音色（声音复刻 · 用你自己的录音）

**手里已经有录音时走这条**，复刻出来的音色比文字描述像得多：

1. 「自建音色 · 声音复刻」里点「**选择文件…**」选一段录音（WAV / MP3 / M4A），**选完立刻自动体检**，也会把体检结果写在下面的状态框里
2. 想单独再体检一次就点「**体检这段录音**」——这一步不花钱、不联网
3. 需要的话填**音色名**（前缀，只能数字/字母/下划线，≤16 字符）和**录音文本**（可选，填了相似度更好，但**必须和录音内容完全一致**，填错反而会触发降级）
4. 点「**用这段录音创建音色并试听**」。成功后音色自动进列表、「合成模型」自动切到 `qwen3-tts-vc-2026-01-22`，并且**直接用新音色读一遍试听框里的文本给你听**（复刻接口本身不返回试听音频）

**接口对录音的要求（Qwen-TTS 复刻）**，体检就是照这些查的：

| 项目 | 要求 |
| --- | --- |
| 格式 | WAV（16bit）/ MP3 / M4A |
| 时长 | 推荐 **10~20 秒**，至少 3 秒连续人声，最多 60 秒 |
| 大小 | ≤ 10 MB |
| 采样率 | ≥ 24 kHz |
| 声道 | **单声道** |
| 内容 | 连续清晰的朗读，无背景音乐/噪音/第二个人声，停顿 ≤ 2 秒；不要唱歌 |

**本地能自动修的，我直接修好再上传**，并在状态框里逐条告诉你改了什么：

- 双声道 → **混合成单声道**（取各声道平均）
- 低于 24 kHz → **线性插值重采样到 24 kHz**（只是补点达标，不会真的变清晰，这点不骗你）
- 8bit / 32bit → **转成 16bit**
- 超过 60 秒 → 会先问你，同意才**截取开头 30 秒**

**本地修不了、会直接拦下不浪费调用的**：文件太短（< 3 秒）、几乎没声音（峰值 < 500/32767）、大于 10 MB、格式不对。

关于 MP3 / M4A，说实话：**本地没有解码器，读不出时长和采样率**，只能查扩展名和大小，其余交给接口判断。想先自己确认参数，用系统自带播放器看一眼，或者转成 WAV 再选——转成 WAV 就能本地体检了。

复刻相关实话：

- **每个音色 0.01 元**（北京地域开通后 90 天内送 1000 次免费额度，创建失败不计费）
- 音色在创建时**绑定**驱动模型，不能跨模型使用；**合成时 model 必须与创建时一致**
- 别把驱动模型改成 `qwen3-tts-vc-realtime-*`：实时版只能走 WebSocket，界面会拦下并提示
- 如果接口返回 `fallback_mode`（降级模式），说明音色是「凑合」建的，相似度可能不理想，原因（如 `no_valid_asr_segments` = 音频和文本严重不匹配）会原样写在状态框里
- 声音设计（描述生成）和声音复刻（录音生成）的音色挂在不同的 model 下，「列出我的自建音色」会**两边都查**并合并显示，某一边查失败也会告诉你

## 屏幕理解（角色看你的屏幕，主动搭话）

开启后角色会**时不时截一张图**交给视觉模型，让它以角色口吻说一句，再走**和回复同一条语音链路**读出来。

**优先级是硬规则：用户输入 > 屏幕内容。**

| 情形 | 行为 |
| --- | --- |
| 用户刚说过话（默认 45 秒内） | **不看**屏幕，把关注留给用户 |
| 角色正在回复用户 | **不看** |
| 看一眼的过程中用户发话了 | 这次观察结果**直接丢弃**，绝不插嘴盖过用户 |
| 用户长时间没动静、画面也变了 | 才看一眼，说一句 |

### 隐私（这块是可开关、可限范围的）

- **默认关闭**（`screen_enabled: false`），不主动开就永远不会截屏
- 截图**只在内存里**传给视觉模型，**不落盘**（不生成任何图片文件）
- 识别结果**不写进对话数据库**——屏幕内容不会留在磁盘上，也不会污染对话上下文
- 范围三选一：**整屏 / 划定区域 / 锁定窗口**（锁窗口会跟着窗口移动，窗口关掉会明确报错而不是乱截）
- 上传前把长边缩到 `screen_max_edge`（默认 1280），既省 token 也少暴露细节
- 节奏可调：最短间隔（默认 30 秒）、用户静默多久才允许看（默认 45 秒）、**画面没变化就不重复看**

### 独立 API

`screen_*` 一组键，和聊天模型分开配——因为能看图的模型往往不是平时聊天的那个（DeepSeek 就不吃图片）。
界面里有个「**沿用聊天 API 的地址/Key/模型**」按钮可以一键抄过来。

**本机实测**：现有的中继（`https://你的中转站域名`）+ `你的视觉模型` **确实能看图**。
探测时我发了一张深蓝底、写了 `LILYZ` 的测试图，模型答「蓝色背景上有一排五个白色空心小方框」——
那张图因为环境缺字体，`LILYZ` 真的被渲染成了 5 个空心方框，所以它是在**读像素**，不是背内容。

### 设置（工作台 ⚙ → 屏幕理解设置）

| 区域 | 内容 |
| --- | --- |

## 回复气泡的位置

气泡**不再是「窗口上方居中」硬贴**，而是从角色当前帧里**量出头顶在哪**再定位：

1. 把当前帧转成图像，从上往下扫第一条不透明像素带 → 取它的水平中心与左右范围，当「头顶锚点」（换素材、换方向都跟着走）
2. **定位的是尾巴，不是气泡边**：尾巴正对头顶中心，气泡于是自然朝**右上方**铺开（尾巴落在气泡宽度 18% 处）
3. 头顶上面没地方（角色贴着屏幕顶部）→ 自动**翻到下方**，尾巴朝上指着头
4. 右边放不下 → 镜像到左侧，尾巴仍在头顶上方
5. 最后按**当前屏幕的工作区**夹一次，气泡不会跑到屏幕外或多屏缝里

另外修了一个「第一次出现位置不对」的 bug：`show_text()` 是先定位再 `show()`，而定位函数为了省开销会跳过隐藏状态 —— 于是气泡第一次弹出时停在 (0,0) 左上角，要等角色移动才跳到位。现在首帧强制定位。

> 想看效果：用你自己的角色素材启动就能看到（角色贴屏幕顶时气泡会自动翻到下方、尾巴朝上；常规情况在头顶右上方）。原示意图画的是作者的私人角色，所以没有随包附带。

## 窗口大小（都能拖边框改大小，不会顶出屏幕）

所有设置类窗口都：

- **初始大小被夹在屏幕可用区域内**（最多占 95% 宽 / 90% 高，任务栏算在内），打开就看得全；
- **可以拖边框改大小**，右下角有尺寸手柄，鼠标指到边框时光标会变成对应的缩放箭头；
- 内容很高的窗口（**语音合成设置**、**屏幕理解设置**）内容放在**滚动区**里：窗口拖到再小，滚一下也能看到全部；**「保存 / 取消」按钮固定在底部**，不跟着滚走。

以前是写死的 `resize(820, 760)`，屏幕不够高时窗口直接顶到屏幕外，底部的按钮永远看不见——这就是你遇到的那个问题。

**聊天输入窗**（无边框）也能拖边框改大小：按住左右边可改宽度、上下边改高度、四角同时改。
它默认还是「高度跟着输入内容自动长」，但你**手动拖过高度之后就听你的**，不再自动顶回去。
往桌宠下方固定时会自动夹在屏幕工作区内。

> **对话气泡**故意不给手动拖大小：它按文字自动量宽高、尾巴锚在角色头顶，手动拖会跟自动排版打架，
> 而且它本来就会被夹在屏幕内。桌宠本体的缩放见下面一节。

### 桌宠大小（缩放 40%~300%）

三个入口，随便哪个都行：

| 入口 | 怎么用 |
| --- | --- |
| **右键桌宠 → 调整大小** | 子菜单标题就写着当前百分比；里面有「放大一点 / 缩小一点」（每次 10%），和 60% / 80% / **100%** / 130% / 160% / 200% 六个档位 |
| **按住 Ctrl 滚轮** | 在桌宠身上滚，每次 5%，适合微调 |
| **工作台 → 桌宠大小滑块** | 拖的时候实时预览，松手才写进配置 |

- 范围 **40%~300%**（1.0 = 原来的 256px 窗口）。100% 时窗口还是 256×256，和以前完全一样。
- **锚点是「脚」**（底边中心），不是窗口中心：放大时角色是往上长，不会整只飘起来；缩小时往下收。
- 放得太大顶到屏幕边时，会自动把窗口**夹回工作区**，不会半只跑到屏幕外。
- 大小写进 `config.json` 的 `pet_scale`，**下次启动还是你调好的大小**。
- 画质：源帧是 1254×1254 的 PNG，放大到 3 倍（768px）仍然比源图小，所以不会糊。
  只有源素材本身很小（比如 128px 的帧）放大才会发虚——那种情况右键菜单把「清晰渲染」关掉会更锐利。

> 为什么 Ctrl+滚轮要按 Ctrl：桌宠是无边框置顶窗口，不设条件的话，鼠标停在它身上滚页面会被它吃掉。

## 对话 API 与多套第三方接口（工作台右键 → API 配置）

对话框顶部多了一块「**已保存的接口**」，可以把**好几个自己填的第三方 API** 存起来随时切换：

| 按钮 | 做什么 |
| --- | --- |
| **增加** | 把下面填的这一套（Provider / 模型 / API Key / 地址 / 最大回复 token）存成一个**新档位**，会问你起个名字（默认拿模型名） |
| **改名** | 给选中的档位换个名字 |
| **更新为当前填写** | 用下面填的内容**覆盖**选中的那一档（会先确认） |
| **删除** | 删掉选中的档位（会先确认；只删这一档，**桌宠当前在用的配置不受影响**） |

**两块各管各的**（这点容易混，界面上也写了）：

- **增加 / 更新 / 改名 / 删除 = 管「库」**：**点下去就立刻写进 `config.json`**。所以即使随后点「取消」，刚存的档位也不会丢。
- **最下面的「保存」= 管「现在用哪套」**：把当前字段写进生效配置并重建 provider，桌宠立刻改用它。

选中库里某一档 → 下面的字段自动填好 → 点「保存」就切过去了。顶部会显示两行状态（**实时更新**，边打字边变）：

```
当前桌宠在用：阿里 ｜ compatible ｜ qwen-flash ｜ https://dashscope.aliyuncs.com/compatible-mode/v1 ｜ Key 有 ｜ 500 token
下面这套 == 档位「阿里」，也就是当前在用的
```

如果当前字段和任何档位都不一样，第二行会变成醒目的黄底警告：
「**⚠ 下面这套还没存进任何档位**：点「增加」存成新档，或点「更新为当前填写」覆盖选中的那一档」。

**「增加」存的是点它那一刻的字段**。所以顺序很重要：想让某一档记住新地址/新 Key，
要么**先填好再点「增加」**，要么填好之后点「**更新为当前填写**」。为了让顺序错了也不会白干：

| 你做的事 | 现在的行为 |
| --- | --- |
| 改了字段、没进任何档，直接点「保存」 | 会**主动问**「这套配置还没存进任何档位，要存成一个新档位吗？」——选「存成新档再保存」就顺手存下来，不会像以前那样只是默默生效、档位里啥也没有 |
| 改了字段，又去点库里另一档 | 会**先问**：「下面这套还没存进任何档位，切过去会覆盖掉」——可以「先存成新档」「放弃改动切过去」或「取消」 |
| 改了字段，想反悔变回这一档 | **再点一次同一档**就行（Qt 对「选同一项」不发切换事件，这里专门接了 `activated`，所以重复点也有效） |

细节：

- 打开对话框时**不会**用库里的副本覆盖字段（否则你手动改过 Key 就会被库里的旧值顶掉）。
- 删掉的正好是当前档位时，`api_profile` 会清空，但 `provider / model / api_key / url` 这些生效配置**原样保留**。
- 拦截关键词、停止词属于「回复过滤」，不属于某个接口，所以**不跟着档位走**。
- **API Key 就存在 `config.json` 里**（和原来那一个 Key 的存放方式相同，没有额外加密/钥匙串）。

相关配置：`api_profiles`（档位列表）、`api_profile`（当前生效的档位名）。

> 顺手修的一个老毛病：Qt **不会**按系统语言自动加载翻译，所以以前所有标准按钮都是英文的
> （Save / Cancel / OK / Yes / No），哪怕系统是中文。现在启动时会加载 `qtbase_zh_CN`，
> 全应用统一成「保存 / 取消 / 确定 / 是 / 否」；万一找不到翻译文件，日志里会写一条警告，按钮回落成英文。

## 接口出错时怎么办（504 / 超时 / 报错串）

聊天/视觉接口出错时，provider **不抛异常，而是返回一句以「暂时无法连接」开头的话**。所以任何"把返回值当正文用"的地方都必须先过 `is_error()` 判断，否则会出事 —— 实测就出过一次：中继偶发 **504 Gateway Time-out**，那句话被当成角色台词显示在气泡里，还被 TTS **一字不差地念了出来**。

现在的处理：

| 环节 | 行为 |
| --- | --- |
| **自动重试** | 5xx / 429 / 408 / 425 一律重试，最多 3 次、间隔递增（1.5s / 3s）。中继的 504 多是偶发，实测第 2 次就成功了。4xx（比如 Key 错、参数错）**不重试**，没意义 |
| **不当台词** | 会话层识别到错误串后：写 ERROR 日志、走 `error_received` 信号，**不进气泡当台词、不进数据库、绝不朗读** |
| **仍然可见** | 气泡里会显示「（接口出错：… HTTP 504 …）」——明确标成接口问题，不会让你以为是角色在说话 |
| **日志** | `llm` 记录每次重试；`conversation` 记录「模型接口报错：…」原文 |

> 判断依据集中在 `llm_provider.ERROR_PREFIX` / `is_error()` 一处，不再靠各处硬编码字符串。

## 表情（让模型决定露什么表情）


**可行，而且底层早就通了**：`SpriteSheet` 里本来就有 `expressions()` / `set_expression()`，右键菜单的「切换表情」就是它在用。缺的只是**素材**和**让模型去选**这两件事。

### 素材怎么放

```
assets/characters/回末李花子/expressions/
    开心/
        N/  000_开心.png  001_开心.png ...
        NE/ ...
        E/  ...
        ...（八个方向）
    生气/
        ...
```

- 目录名就是**表情名**，也是模型能选的名字（白名单）
- 和动作一样按方向分子目录；**只画了部分方向也能用**——缺的方向会自动取同一表情里最近的、有图的方向（不会因为转个头表情就没了）
- 某个表情一张图都没有时，该表情会退回当前动作的帧（不会空白）
- 帧文件按文件名排序播放，可在目录里放 `durations.json` 控制每帧时长（和动作同规则）
- 没素材时：不会给模型发「可以选表情」的说明，也不会解析标签——功能静默关闭，不会瞎猜

### 模型怎么指定（标签协议）

系统提示里会带上一句（只在表情名非空时才加）：

> 如果你想让角色露出某个表情，就在回复最前面写一个标记：`[表情:名字]`，名字只能从这个列表里选：开心、生气。没有合适的就不要写，不要自己造名字。

实际回复长这样：`[表情:开心]你好呀，今天也要一起玩吗？`

处理规则：

| 情况 | 行为 |
| --- | --- |
| 名字在白名单里 | 换上该表情，`expression_hold_seconds`（默认 5 秒）后自动收回 |
| 名字**不在**白名单里 | 标记照旧从正文里删掉，但**不换表情**，并在日志里记一条（方便发现模型乱造词） |
| 全角/半角括号都认 | `[表情:x]`、`【表情：x】`、`（表情:x）`、`(表情: x)` |
| 标记出现在句中 | 一样会被摘掉 |
| 整句只有标记 | 摘完就是空，不会发出空回复 |

**标记绝不会被念出来**：正文先摘标签、再进气泡和语音合成，所以 TTS 读到的永远是干净的句子。

### 与手动表情的关系

右键菜单里选的表情是**常态**（用户说了算）；模型指定的是**临时**的，到点后回到手动选的那个。这样你手动设了「生气」，模型插一句「开心」不会把它永久顶掉。

### 相关配置

| 配置项 | 说明 |
| --- | --- |
| `expression_enabled` | 是否允许模型指定表情（默认 `true`；没有素材时自动等于关闭） |
| `expression_hold_seconds` | 表情保持多久后自动收回（默认 5 秒） |

> 想让模型更爱用表情，可以在「角色提示词」里加一句倾向；想让动作和表情配合（比如换表情时顺手换动作），目前要手动在右键菜单里切——**动作和表情是两套独立素材**，各自有方向帧。

## 无方向动作与待机轮播（八方向不用画两套）

**八方向那套只画一套就够**：它专门给鼠标追踪用。待机这类动作本来就没有朝向可言（发呆、打盹、玩手指），画八向纯属浪费——现在**不分子目录**就能直接用。

### 素材怎么放（两种动作共存）

```
assets/characters/回末李花子/motions/
    idle/                 ← 有方向：八向追踪动作
        N/ 000_睁眼.png 001_半闭.png ...
        NE/ ... E/ ... （八个方向）
    呆站/                 ← 无方向：PNG 直接放这一层，没有任何子目录
        000_呆站.png 001_呆站.png 002_呆站.png
        durations.json    ← 可选，格式和动作一致
    打盹/
    玩手/
```

判定是自动的：目录下直接躺着 PNG → 无方向动作；只有 `N/E/S…` 子目录里有图 → 八方向动作。

### 行为

| 条件 | 行为 |
| --- | --- |
| 鼠标在动（或刚动过） | 用**八方向追踪动作**，跟着鼠标转头，眨眼照旧 |
| 鼠标一直不动超过 `idle_after_seconds`（默认 20 秒） | 切进**待机模式**：从无方向动作里**随机挑一个**播放 |
| 每个待机播放满 `idle_motion_seconds`（默认 10 秒） | 随机换下一个，**不会连着两次播同一个** |
| 鼠标一动 | 立刻退出待机，回到八方向追踪动作，并**保留当前朝向**（不会先跳回正面） |

- 待机模式里不做朝向判定（那套素材没有方向），帧按自己的 `durations.json` 播
- **没有无方向素材时整套逻辑自动失效**，行为跟以前完全一样
- 工作台点「Ⅱ 暂停」时，待机计时也一起停

### 怎么建（工作台里就能建，不用手改目录）

| 操作 | 结果 |
| --- | --- |
| 动作列表右键 →「**新建动作**」 | 会**先问你**：八方向（跟随鼠标转头，自动建好 `N/E/S…` 八个目录）还是无方向（帧放一起，待机用） |
| ⚙ → 待机动作设置 →「**新建无方向动作**」 | 直接建一个不带方向子目录的动作，切过去导入帧 |
| 动作列表右键 →「**转为无方向动作**」 | 把已经建成八方向的动作（比如建错的「发呆」）各方向帧**收进动作根目录**、删掉方向子目录；文件名冲突时自动加方向前缀，`durations.json` 会一起并过来（时长不会丢） |

导入帧落在哪儿是自动判断的：已经有帧就按现状走；**还没有帧**时看它有没有 `N/E/S…` 子目录——有就放进方向目录，没有就放进动作根目录。所以「新建无方向动作 → 导入多帧」不会再被塞进方向目录里（这正是之前建不出无方向多帧的原因）。

**界面会跟着变**：选中无方向动作时，帧序列右上角的「方向」直接显示成「**无方向（帧按顺序播）**」并置灰，八个方向按钮一起禁用（它们对无方向动作没有任何意义）；选中无方向的表情也一样。旁边还有个「**转为无方向**」按钮，一键把当前有方向动作的各方向帧收进根目录（就是右键菜单里那个，放在方向旁边更顺手）。

### 设置（工作台 ⚙ → 待机动作设置）

- **追踪动作（八方向）**：哪个动作负责跟随鼠标
- **待机动作**：勾选哪些无方向动作参与轮播；**一个都不勾 = 自动使用全部无方向动作**
  - 列表里会**列出全部动作并注明原因**：`发呆（3 帧，可以当待机）` / `idle（八方向动作，不能当待机）` / `蝴蝶（还没有帧：先选中它 →「＋ 导入 PNG 帧」）`。只有能用的才允许打勾
- **静止多久进入待机** / **每个待机播多久**
- 「**新建无方向动作**」直接建一个不带方向子目录的动作
- 「**立刻试一下待机**」不用干等静止计时，马上切到待机动作看一眼（鼠标一动就会自己切回去）
- 保存后**立即生效**，不用重启

> 新建动作时那个「八方向 / 无方向」的选择框，现在是**中文按钮**（以前用系统 Yes/No/Cancel，Qt 默认不带中文翻译，看起来就不知道在问什么）。导入帧之后也会明确告诉你「导到哪个目录、这个动作现在是什么类型、共几帧」。

### 待机不生效？按这个顺序查

日志里 `pet` 开头那几行会写清楚：

| 日志 | 含义 |
| --- | --- |
| `动作规划：追踪=idle…｜待机=['发呆']` | 已识别到待机动作，池子正确 |
| `动作规划：追踪=idle…｜待机=无` | **没识别到无方向素材**：动作目录下没有直接放 PNG（可能帧还在方向子目录里，用「转为无方向」） |
| `鼠标静止够了，进入待机动作（池：…）` | 真的进了待机模式 |
| `该进待机了，但没进：playing=… 待机池=…` | 被暂停了，或池子是空的 |
| `鼠标动了，退出待机动作，回到 idle` | 鼠标一动就切回去了（这是设计行为） |

常见「看着没动静」的原因：

1. **鼠标一直在动** → 待机永远不会触发（这是优先级设计）。手离开鼠标等满「静止秒数」再看，或直接点「立刻试一下待机」
2. **待机动作只有 1 帧**，或几帧长得几乎一样（比如导入了 `睁眼/半闭/闭眼` 但没设时长）→ 画面看着就是静的。到帧列表里给每帧单独设时长，例如睁眼 `1600`、半闭 `120`、闭眼 `80`、半闭 `120`，这样才看得出"眨眼/呼吸"的节奏
3. 之前点过方向按钮会把「跟随鼠标方向」取消勾选 —— 早期版本这会连带让待机逻辑一起失效（已修）
4. 拖动帧顺序后，帧列表/角色变成**占位图**？这是无方向动作的帧缓存不失效导致的（旧版本：缓存按「动作/方向」子目录的 mtime 判断，无方向动作没这个目录，于是永远返回旧文件名）。现在缓存按**实际会扫的目录**判断，并在一处改动素材后主动清缓存，重排/导入/改名/删除都会立刻反映出来

### 相关配置

| 配置项 | 说明 |
| --- | --- |
| `tracking_motion` | 鼠标追踪用的八方向动作名；留空 = 自动取第一个有八方向的动作 |
| `idle_motions` | 待机轮播用哪些动作；空列表 = 自动收集所有无方向动作 |
| `idle_after_seconds` | 鼠标静止多久进入待机（默认 20 秒） |
| `idle_motion_seconds` | 每个待机动作播放多久换下一个（默认 10 秒） |





工作台右侧有两个滑块：

| 滑块 | 作用 |
| --- | --- |
| **视线灵敏度** | 角色转头跟随鼠标的频率，20–400ms（越小越跟手）。默认 50ms |
| **帧间隔** | 动画帧的兜底时长。idle 的每一帧都在 `durations.json` 里写死了时长，所以这个滑块对 idle 不生效 |

**视线追踪和眨眼用的是两个独立定时器**：追踪走高频定时器（默认 50ms），眨眼按每帧的 `durations.json` 走。

### 什么时候眨眼

规则是**鼠标在动就不眨眼**：

| 状态 | 表现 |
| --- | --- |
| 光标移动中（或方向变化中） | 保持睁眼，不眨眼 |
| 光标停稳超过「一次完整眨眼动画时长 × 0.5」 | 从睁眼帧开始正常眨眼 |

等待门槛是按当前动作的 `durations.json` **算出来的**，不是写死的：idle 各帧取上限 1600+80+60+80+1000 = 2820ms，**乘 0.5 得到 1410ms**。

比例由 `PetWindow.SETTLE_RATIO` 控制：`1.0` 表示一次眨眼绝不会被打断，但停手后要等满一个周期；`0.5` 恢复快一倍，偶尔会眨到一半被鼠标打断。另有 `SETTLE_MIN_MS = 300` 兜底，防止帧时长很短时变得神经质。

眨眼途中被叫停会**立刻回到睁眼帧**——这是刻意的：转身过程中眨到一半看着更怪。

实测时序（鼠标在 0~1000ms 持续移动，之后停住）：

```
鼠标停下后恢复眨眼的时刻 = 2419 ms
  期望 1000 + 1410 = 2410 ms
  （改之前用满周期，是 1000 + 2820 = 3820 ms）
```

光标只有移动超过 3px 才算「在动」，这样能滤掉鼠标自身的微小抖动。

### 觉得「卡」时先看这里

实测数据（8 方向 × 5 帧 = 40 张，共 29.6 MB）：

| 项目 | 开销 |
| --- | --- |
| 每次换方向 + 重绘 | **0.53 ms** → 20ms 追踪下约 3% CPU |
| 帧列表查询（带缓存） | 0.11 ms |
| 时长查询（带缓存） | 0.11 ms |

**帧数不是瓶颈**——40 帧在最高追踪频率下也只用 3% CPU。真正会造成卡顿的是这三件事，都已经处理：

1. **每次重绘都从磁盘解码原图**：素材是 1254×1254 的 PNG，解一张要 30–40ms。现在缩放结果会缓存（缓存键含文件修改时间，换素材自动失效），并在启动后台逐张预热。

2. **转向会打断动画**：这条最隐蔽。原来的逻辑是「换方向 → 帧号归零 + 重启动画计时器」，而 idle 每帧时长是 1000~1600ms（其它动作只有 125ms）。鼠标持续移动时方向不断变化，那台计时器被**反复重启**，永远走不到下一次触发——动画整个冻在睁眼帧，表现就是又卡又迟钝，而且**帧时长越长的动作越明显**。

   现在**转向完全不碰动画**：不重置帧号、不重启计时器。朝向和眨眼是两件独立的事，转头不再影响眨眼节奏。

3. **方向在分界线上反复横跳**：光标停在两个方向的交界处时，一点点抖动就会让方向以追踪频率疯狂左右翻。现在用**角度死区**：离开当前朝向中心超过 `22.5° + 8°` 才切换。实测在分界线上抖动 200 次，换向从 **106 次降到 0 次**；而真实扫过时只在 33°/78° 处切换（比理论边界晚 9°，察觉不到）。

   死区比之前的「连续命中 3 次」方案更好：**真实转动是立刻响应的**，不需要多等几十毫秒。

另外光标离角色中心 24px 内不做判定——那个距离下角度毫无意义，一点点位移就能绕好几圈。

## 只用模型自身知识（完全不联网）

想让模型凭自己训练数据里的知识整理，不发起任何检索：

| 配置项 | 设成 |
| --- | --- |
| 允许 API 自身联网检索 | **取消勾选** |
| 联网后端 | **`off`** |

此时搜集不会碰网络，条目来源如实写成「模型已有知识」，不会编造链接。

> ⚠️ **这种模式下务必用最强的模型。** 没有联网核验时你无法从输出里分辨哪些是编的——实测同一个角色、同一份提示词：
>
> - `deepseek-chat`（2.5 秒）把回末李花子说成《壳之少女》里的**侦探助手**，作品名和职业全错，语气却和真事实一样笃定；
> - `某个推理模型`（199 秒）给出《人狼村之谜》、休水村回末家、房石阳明等**全部正确**的信息。
>
> 用错的模型不会报错，只会安静地往知识库里灌假事实。用快模型省下的时间，会以「知识库全是错的」的形式还回来。

另外 `knowledge_util_model`（查重、文档归纳用的快模型）在这种模式下**不要**拿来当主模型——它就是上面那个会编故事的模型。

### 更稳妥的替代做法：导入你自己的资料

如果只是想避开联网，而不是非要用模型的记忆，**导入文档**往往更好：把原著片段或你整理的资料丢进去，模型只负责抽取、不能自由发挥，这时用快模型也不会跑偏。两者也可以叠加——先让强模型凭自身知识搜集，再导入资料补充和纠错，最后用「检测并清理重复」合并。

## 知识库联网组件（web_tools.py）

知识库的「联网搜集」有**两条互相独立**的路径，可以只开一条，也可以同时开（推荐同时开）：

| 路径 | 开关 | 需要额外 Key？ | 说明 |
| --- | --- | --- | --- |
| **API 自身联网** | 允许 API 自身联网检索 | **不需要** | 模型自己去搜。走 `/v1/responses` + `tools:[{"type":"web_search"}]` |
| **本地联网组件** | 联网后端 ≠ `off` | 一般不需要 | `web_tools` 先搜好网页再喂给模型，任何模型都能用，来源 URL 明确 |

### 推荐配置：Bing 负责搜，API 只负责整理
**这是最稳的用法，不依赖任何特定模型。** 搜索交给本地组件（免 Key、免费、结果带真实 URL），API 只做信息抽取整理——所以就算 `某个推理模型` 哪天改名或下线，换成任意对话模型照样能用。

| 配置项 | 推荐值 |
| --- | --- |
| 允许 API 自身联网检索 | **不勾选** |
| 联网后端 | `bing`（免 Key） |
| 抓正文页数 | 3~6 |
| 知识库模型 | 任意对话模型。实测 `某个推理模型` 与 `deepseek-flash` 都能胜任 |
| 最大 token | **≥ 8000**（推理模型的思维链很吃 token，太小会导致正文为空） |

「API 自身联网检索」是可选的加成，只有服务商和模型**都**支持时才有效，不开完全不影响搜集。它是这条链路里最脆弱的一环：依赖特定模型、单次 3 万+ 输入 token。默认已关闭。

### 搜集结果会如实汇报

搜集完成后，界面状态栏会写明**实际**发生了什么，不会把降级包装成成功。例如：

```
完成：新增 5 条，等待审核（本地 bing 搜到 5 个来源；API 自身联网不可用：模型收下了联网工具但没有真的去搜）
```

同样的内容也会记进 `app.log` 与知识库的 `last_note`。API 联网失败时会自动改回普通接口继续用本地结果，**但一定会告诉你**，不会静默糊弄过去。

### 为什么模型 API 有的能联网、有的不能

「联网」不是模型接口的通用能力，而是服务商自己实现的工具。实测结论：

| 调用方式 | 结果 |
| --- | --- |
| `chat/completions` | ❌ 不支持联网 |
| `/v1/responses` + `tools:[{"type":"web_search_preview"}]` | ❌ 报 `Unsupported tool type`（旧工具名） |
| `/v1/responses` + `tools:[{"type":"web_search"}]` | ✅ 可用，但**是否真搜取决于模型** |

⚠️ **同一个服务商下，不同模型能力可能完全不同。** 实测 DeepSeek：

| 模型 | 是否真的联网 |
| --- | --- |
| `某个推理模型` | ✅ 真搜。实测一次提问产生 10 次 `web_search_call`，输入 33871 token 的真实网页内容 |
| `deepseek-flash` | ❌ **假搜**。接口接受了工具却一次搜索都不发，然后凭训练数据**编出「来源链接」** |

假搜比不联网更危险——它会往知识库写看起来很可信、实际是编造的来源。所以程序会**核对真实的搜索调用次数**：为 0 就判定「没联网」，丢弃这次结果、回退到本地检索 + 模型已有知识，绝不让编造的来源入库。

### 推理模型需要更大的「最大 token」

`deepseek-flash` 这类推理模型会先输出一大段思维链。实测一次回答里 `reasoning_tokens` 占 2852/3000——如果「最大 token」设小了（比如 2000），token 全被思维链吃掉，正文就是空字符串，表现为「API 返回为空」。**建议至少 8000。**

### API 联网失败不会中断搜集

任何一环失败都只降级、不终止：API 自身联网失败 → 自动改回普通接口，用本地检索结果继续；本地检索失败 → 用模型已有知识继续（并如实标注 source，不编链接）。只有主动勾选「联网兜底＝检索失败就中止」才会停下。

### 本地联网的后端

`auto` / `bing` / `searxng` / `tavily` / `bocha` / `zhipu` / `serper` / `brave` / `duckduckgo` / `wikipedia` / `off`。

只有 tavily / bocha / zhipu / serper / brave 需要 Key；bing、searxng、duckduckgo、wikipedia 免填。

后端可达性因网络而异。实测国内网络下 **`bing`（Bing 的 RSS 输出）免 Key 可直连且结果干净**，故 `auto` 默认优先用它；DuckDuckGo 与 Wikipedia 在国内多数网络超时，只作最后兜底。

### 配置项（⚙ → 角色知识库 → 知识库 API 与提示词设置）

| 配置项 | 说明 |
| --- | --- |
| 允许 API 自身联网检索 | 走 `/responses` 的 `web_search`，模型自己搜 |
| 联网后端 | 本地组件；选 `off` 表示不用本地检索，只靠上面那条 |
| 联网 Key | 仅 tavily / bocha / zhipu / serper / brave 需要 |
| SearXNG 地址 | 仅 `searxng` 用，需实例已开启 `format=json` |
| 检索词模板 | 默认 `{name}`，可用 `{description}`；多条查询用 `\|` 分隔 |
| 抓正文页数 / 每页字数 / 联网超时 | 本地组件的抓取规模与超时 |
| 联网兜底 | 勾选＝本地检索失败就中止；不勾＝继续（若 API 联网开着就交给它） |
| 请求方式 | 流式请求。长提示词必须开，否则中继的 nginx 网关常回 504 |
| 待审核条目也用于对话 | 见下节 |
| 没有关键词命中时也注入核心设定 | 问「今天天气」这类问题时也带上角色底色 |
| 联网自检 | 用当前设置真实检索一次并报告命中的后端与结果 |

### 抓不到结果怎么办

先点「联网自检」。若所有后端都为空，通常是网络/代理不通或后端需要 Key；此时换成国内可直连的搜索 API 最省事：

- **Bocha（博查）**：`https://api.bocha.cn/v1/web-search`，中文效果好，`open.bocha.cn` 领 Key
- **智谱 Web Search**：`open.bigmodel.cn` 领 Key，后端选 `zhipu`
- **Tavily**：`tavily.com` 领 Key，专为 LLM 设计，每月有免费额度

## 导入文档归纳

联网搜到的资料往往不够全（冷门角色尤其如此）。你可以把**自己整理的资料、原著小说、设定集、同人考据**导入，让 API 归纳成知识条目入库。

在「角色知识库」面板点 **导入文档归纳（txt / md / html，可多选）**：

1. 选文件 → 长文档自动**分块**（默认 6000 字一块，块间留 300 字重叠，避免把一条事实切成两半）
2. 每块交给模型抽取，**只依据材料本身**，明确禁止模型拿自己的先验知识补充——否则就失去了「导入资料」的意义
3. 抽出的条目以**文件名作为来源**入库，状态仍为待审核；重复的自动跳过

小说 txt 常是 GBK 编码，读取时会依次尝试 UTF-8 / GB18030，不会读成乱码。

| 配置项 | 说明 |
| --- | --- |
| `knowledge_import_chunk_chars` | 每块字数，默认 6000 |
| `knowledge_import_overlap` | 块间重叠字数，默认 300 |
| `knowledge_import_max_chunks` | 单次最多处理多少块，默认 30（防止一次导入整本小说把额度跑光） |
| `knowledge_import_prompt` | 归纳提示词，留空用内置默认（可用 `{name}` `{source}` 占位） |

## 检测并清理重复

多次采集 + 导入之后，库里一定会有重复。点 **检测并清理重复**：

- **默认用 API 做语义查重**，因为字面查重对改写完全无效——实测库里三条「…是《人狼村之谜》的角色」的不同措辞，字面相似度最高只有 0.76，按字面一条都找不出来。
- 结果会**列出来让你逐组看过再确认**，不会直接删。每组保留「已确认 / 内容更完整」的那条。
- **删除前会先合并**：如果被删条目里有保留项没写到的独有细节（比如保留项写了感情线、被删项还写了「照顾幼女咩子」），模型会把那些细节并进保留项再删，避免丢信息。
- 要删的条目超过半数时会额外警示。
- 新采集/导入时也会顺手做一次字面查重（`knowledge_dedupe_threshold`，默认 0.75），挡住明显的重复。

## 工具调用要用快模型（重要）

查重和文档归纳这类**输入短、输出短**的任务，用重推理模型会非常慢：实测 `某个推理模型` 查一次重要 **73 秒还返回空**，而 `deepseek-chat` 只要 **1 秒**。

所以这两类调用走独立的 `knowledge_util_model`（留空则沿用主模型）：

| 用途 | 用哪个模型 | 建议 |
| --- | --- | --- |
| 联网采集（要用 API 自身联网时） | `knowledge_api_model` | 必须是真会联网的模型 |
| 查重、文档归纳 | `knowledge_util_model` | 用快的小模型，如 `deepseek-chat` |

## 知识库怎么进入对话

命中的知识会拼进系统提示词。两个关键点：

1. **待审核条目同样参与对话**，不需要先逐条点「标记已确认」（可用 `knowledge_use_pending` 关掉）。采集结果默认待审核只是为了让你事后核对，不是使用门槛。
2. 检索用 **2~4 字 n-gram 打分**匹配。中文消息没有空格，早期版本按空格分词后拿整句话去做 `LIKE '%整句%'`，导致采集来的知识几乎永远匹配不上、进不了对话——现已修正。

没有任何关键词命中时，会兜底注入少量核心设定（`knowledge_always_inject`）；注入总量受 `knowledge_max_chars` 限制（默认 1200 字），避免知识库挤掉人设与记忆。

### 排查用的日志

`app.log` 里 `web` 与 `knowledge` 两个 logger 会记录：联网两条路径的开关状态、检索后端尝试顺序与命中数、正文抓取成功数、进入提示词的字数、模型返回的解析方式。返回不是规范 JSON 时会记 `解析方式=lenient/salvaged/raw` 的告警。
